\section{Introduction}
% ============================================================

\subsection{Purpose}

UnitValues is a set of domain-specific typed languages for numerical
quantities. The set consists of two languages:

\begin{itemize}
  \item \texttt{.ut} (unit types) for defining units from fundamental dimensions.
  \item \texttt{.uiv} (unit informed values) which import unit types and use
        dimensional construction to encode numerical quantities.
\end{itemize}

\subsection{Scope}

This document defines the syntax, semantics, and usage of all constructs
in the \texttt{.ut} and \texttt{.uiv} domain-specific languages.

% ============================================================
\section{Language Rules}
% ============================================================

\needspace{3\baselineskip}
\subsection{Global Section}

The \texttt{[version]} section is required and defines the format version:

\needspace{5\baselineskip}
\begin{lstlisting}[language=UnitValuesUT]
[version]
format: 0.1.1
\end{lstlisting}

\needspace{3\baselineskip}
\subsection{Unit Frame}

The \texttt{unit\_frame} directive specifies which \texttt{.ut} file to
import for unit definitions:

\needspace{5\baselineskip}
\begin{lstlisting}[language=UnitValuesUIV]
unit_frame: si_metric.ut
\end{lstlisting}

\needspace{3\baselineskip}
\subsection{Sections}

Sections are denoted by \texttt{[section.name]} and can be nested.
Common section types include:

\begin{itemize}
  \item \texttt{[standards]} --- Defines standard values used across the file.
  \item \texttt{[material.meta]} --- Metadata about a material
        (type, composition, notes).
  \item \texttt{[motor.magnetic]} --- Magnetic properties
        (permeability, hysteresis).
  \item \texttt{[armature.core.slots]} --- Armature slot properties
        (length, material).
\end{itemize}

\newpage

\needspace{3\baselineskip}
\subsection{Value Assignments}

Values are assigned using the format:

\needspace{5\baselineskip}
\begin{lstlisting}[language=UnitValuesUIV]
key: value prefix(unit)
\end{lstlisting}

Examples:

\begin{itemize}
  \item \texttt{density: 8930 (kg/m\string^3)}
  \item \texttt{temperature: 298.15 (K)}
\end{itemize}

\needspace{3\baselineskip}
\subsection{Numeric Values}

UnitValues supports real and complex numerical values. Complex values may
be represented using the standard imaginary unit \texttt{j}:

\needspace{5\baselineskip}
\begin{lstlisting}[language=UnitValuesUIV]
real_value: 12.5 (V)
complex_value: 12.5+3.2j (V)
\end{lstlisting}


\needspace{3\baselineskip}
\subsection{Unit Prefixes}

SI prefixes can be applied to units:

\begin{itemize}
  \item \texttt{(kg/mol)} --- kilogram per mole.
  \item \texttt{M(A/m)} --- mega-amp per meter.
  \item \texttt{m(m)} --- millimeter (i.e., 1/1000 of a meter).
  \item \texttt{m(m\string^2)} --- milli-square-meter
        (i.e., 1/1000 of a square meter).
\end{itemize}

\begin{quote}
  \textbf{Note:} 
  
  Prefixes apply to the unit expression as a whole and do not
  distribute through its internal algebra. For example,
  \texttt{m(m\string^2)} represents $10^{-3}\,\mathrm{m^2}$, not
  $10^{-6}\,\mathrm{m^2}$.
\end{quote}

\needspace{3\baselineskip}
\subsection{Arrays and Tuples}

Arrays are denoted with square brackets:

\needspace{5\baselineskip}
\begin{lstlisting}[language=UnitValuesUIV]
relative_permittivity: [1, 1]
\end{lstlisting}

Tuples (key-value pairs) use nested arrays:

\needspace{5\baselineskip}
\begin{lstlisting}[language=UnitValuesUIV]
temperature_conductivity: [
  [273.0, 401.0],
  [473.0, 389.0]
] (K), (k)
\end{lstlisting}

\begin{quote}
  \textbf{Note:}

  Nested arrays may represent column-wise data. When multiple unit
  expressions follow an array, each unit is assigned to the corresponding
  column. Thus, \texttt{(K), (k)} assigns kelvin to the first column and
  the derived unit \texttt{k} to the second column. The unit \texttt{k}
  is defined in the active unit frame.
\end{quote}

\newpage
\needspace{3\baselineskip}
\subsection{Strings and Comments}

Strings can be used as values:

\needspace{5\baselineskip}
\begin{lstlisting}[language=UnitValuesUIV]
my_spring: "Reduced Order Model | Tubular Ironless Linear Motor"
\end{lstlisting}

Comments begin with \texttt{\#} and extend to the end of the line. Comments
may appear on their own line or after a value:

\needspace{6\baselineskip}
\begin{lstlisting}[language=UnitValuesUIV]
# This is a comment
temperature: 298.15 (K)  # Operating temperature
\end{lstlisting}

\needspace{3\baselineskip}
\subsection{Unit Construction}

Units are constructed from fundamental dimensions using the following
operators:

\begin{table}[H]
  \centering
  \renewcommand{\arraystretch}{1.25}
  \begin{tabular}{>{\raggedright\arraybackslash}p{3.0cm}
                  >{\raggedright\arraybackslash}p{4.0cm}
                  >{\raggedright\arraybackslash}p{7.0cm}}
    \toprule
    \textbf{Operation} & \textbf{Symbols} & \textbf{Description} \\
    \midrule
    Multiplication
      & \texttt{*}, \texttt{x}, $\cdot$, $\bullet$
      & Multiplies units together \\

    Division
      & \texttt{/}, $\div$
      & Divides units \\

    Power
      & \texttt{\string^}
      & Raises a unit to a power \\
    \bottomrule
  \end{tabular}
\end{table}

Examples:

\needspace{5\baselineskip}
\begin{lstlisting}[language=UnitValuesUT]
kg*m^2*s^-3*A^-1
m/s^2
kg*m/s^2
\end{lstlisting}

\section{Examples}
% ============================================================

\needspace{5\baselineskip}
\subsection{.ut File Example}

The following example demonstrates how to define custom units derived from
fundamental dimensions in a \texttt{.ut} file:

\begin{lstlisting}[language=UnitValuesUT]
# Example Units - Derived from Fundamental Dimensions (kg, m, s, A, etc.)
[version]
format: 0.1.1
 
[units]
# name: unit
p: kg*m^-1*s^-2           # Defines the unit for pressure (Pascal)
V: kg*m^2*s^-3*A^-1       # Defines the unit for voltage
\end{lstlisting}

\begin{quote}
  \textbf{Note:}

  The fundamental unit and prefix semantics \texttt{(kg, m, s, A, etc.)}
  \& \texttt{(u, m, k, M, etc.)} is defined by the runtime environment.
\end{quote}

\newpage
\needspace{5\baselineskip}
\subsection{.uiv File Example}

The following example demonstrates how to use unit definitions from a
\texttt{.ut} file and assign typed values in a \texttt{.uiv} file:

\begin{lstlisting}[language=UnitValuesUIV, escapeinside={(*@}{@*)}]
[version]
format: 0.1.1
unit_frame: units.ut

[model]
# name: value prefix(unit)
num_samples: 100                        # Implicitly dimensionless
sample_size: 10         ((*@$\varnothing$@*))             # Explicitly dimensionless
output_energy: 1.0      (kg*m^2*s^-2)   # Defines unit via construction
output_signal: 5.0      (V)             # Defined unit `V` for voltage
inlet_pressure: 101     k(p)            # Defined unit with kilo prefix
\end{lstlisting}

\section{Error Reference}
% ============================================================

\subsection{Errors}

\begin{enumerate}
  \item \textbf{E001} --- ParserError: Generic parser error that occurs when parsing fails. This is a catch-all error for unexpected parsing failures. Raised when a parser encounters an unrecoverable error during parsing.
  
  \item \textbf{E002} --- ParseListFailure: Failed to parse a list or array structure. This occurs when a list definition (e.g., \texttt{[1, 2, 3]} or \texttt{(1, 2)}) is malformed or contains invalid elements that cannot be parsed correctly.
  
  \item \textbf{E003} --- UnknownOperator: Unsupported or unrecognized operator used in unit construction. Valid operators include \texttt{*}, \texttt{/}, \texttt{\^}, etc.
  
  \item \textbf{E004} --- UnknownPrefix: Invalid or unrecognized prefix used in unit definitions. Valid prefixes include standard SI prefixes like \texttt{k}, \texttt{M}, \texttt{m}, \texttt{\textmu}, \texttt{n}, etc.
  
  \item \textbf{E005} --- FailedCasting: Failed to cast a value to a primitive type (e.g., converting a string to float or integer). This typically occurs when a value has an unexpected format that cannot be converted.
  
  \item \textbf{E006} --- ColumnAttribute: Nested array column index is out of range. Occurs when trying to access a column that doesn't exist in a nested array structure during attribute construction.
  
  \item \textbf{E007} --- UnsupportedType: Unsupported type encountered during unit construction. This occurs when a unit or dimensional cannot be converted to a valid unit type because the type is not supported.
  
  \item \textbf{E008} --- UnbalancedDepth: Unbalanced parentheses, brackets, or braces in the input. Occurs when opening and closing delimiters don't match properly during parsing.
  
  \item \textbf{E009} --- InvalidSectionError: Malformed section header in the configuration file. Section headers should follow the pattern \texttt{[SectionName]} and each section name must be a valid Python attribute name.
  
  \item \textbf{E010} --- DuplicateSectionError: Duplicate section found in the file. Each section header must be unique within a configuration file to avoid ambiguity.
  
  \item \textbf{E011} --- InvalidKeyError: Malformed key-value pair. Occurs when a line in a section doesn't follow the key: value format or the key name is not a valid Python attribute name.
  
  \item \textbf{E012} --- UnitNotFoundError: Unit doesn't exist in the current unit frame. Occurs when trying to use a unit that hasn't been defined in the available units list.
\end{enumerate}

\subsection{Warnings}

\begin{enumerate}
  \item \textbf{W001} --- BackCompatibilityWarning: Missing \texttt{format} key in the version section. The file format version is required for proper parsing and backward compatibility with different file versions.
  
  \item \textbf{W002} --- UnitFrameCompatibilityWarning: Missing \texttt{unit\_frame} key in the version section. The unit frame specification is needed for proper unit handling and compatibility with derived units.
\end{enumerate}
